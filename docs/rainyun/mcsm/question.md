# 常见问题

本页汇总 Minecraft 服务端部署中的常见连接、账号、存档和启动问题。排查时应优先查看终端输出与日志，而不是反复重启服务端。

## 连接与登录

### 1. 终端可以执行命令，但客户端找不到服务器

常见报错为 `Connection refused: no further information`。请依次检查：

1. `server.properties` 中的 `server-port` 是否已经改为云服务器或 NAT 映射提供的端口。
2. 客户端填写的服务器地址和外部端口是否正确。

### 2. 导入压缩包后提示缺少 Mod

请确认上传的是**服务端包**，而不是在个人电脑上运行的客户端包。如果文件类型错误，需要重新下载并上传对应服务端。

### 3. 如何导入已有存档

进入`文件管理` → `world/`，停止服务端并备份原存档，然后删除目录内的旧文件，上传已有存档的内部文件进行替换。详细流程参见[更换地图或重置存档](advance.md#更换地图或重置存档)。

### 4. 提示“暂时无法连接至验证服务器，请稍后再试”

可参考[验证服务器连接问题视频](https://www.bilibili.com/video/BV16tejetEUH/)进行排查，同时检查服务器网络、DNS 和 Mojang / Microsoft 验证服务状态。

### 5. 提示“无效会话”

通常有以下两个原因：

1. 客户端使用离线账号，而服务器启用了正版验证。确需允许离线账号时，应关闭 `online-mode`。
2. 启动器中的登录凭据已经过期，需要退出账号并重新登录启动器。

### 6. 提示用户名错误

1. 用户名超过长度限制时，可能出现 `The received string length is longer than Maximum allowed (XX > 16)`。请缩短用户名。
2. 用户名包含非法字符时，可能出现 `Invalid characters in username`。用户名应仅包含英文字母、数字和下划线，即 `A-Za-z0-9_`。

## 性能与启动

### 7. 服务端频繁因 Watchdog 崩溃

1. 检查日志中是否存在 Mod 异常、死循环或区块加载错误。
2. 检查刷铁机、刷怪塔等设施是否产生了异常数量的实体。必要时可执行 `kill @e` 清除所有实体，但该命令也会删除玩家以外的大量实体，执行前必须备份存档并了解影响。
3. 如果实体、区块或 Mod 负载已经超过服务器承载能力，需要优化配置、降低模拟距离或升级服务器。

### 8. 找不到启动脚本（`run.sh` / `start.sh`）

1. 确认上传的是**服务端包**，而不是客户端包。
2. 确认服务端核心已经安装。尚未安装时可参考[视频教程](https://www.bilibili.com/video/BV1GTUhBfETs/)。
3. 如果核心已经安装且文件确认为服务端，请按照[编辑启动脚本](install-mc.md#编辑启动脚本)手动填写命令。

## 获取进一步帮助

::: tip 查找报错日志
服务端崩溃后，打开 `MCSM 面板`并进入`文件管理`：

- `logs/latest.log`：最近一次运行日志。
- `crash-reports/`：最新生成的崩溃报告。

提交问题时建议提供完整文件，不要只截取最后一行错误。
:::

### 1. 使用 AI 辅助分析

可将 `latest.log` 或崩溃报告提供给 AI 工具，请其总结错误链和可能原因。发送前应移除服务器地址、玩家 IP、令牌和其他敏感信息，AI 给出的解决方案也需要人工核对。

### 2. 在交流群寻求帮助

提问时请附上**崩溃后的完整日志**、服务端版本、核心类型、Java 版本和复现步骤。只有截图或单行报错通常不足以定位问题。
