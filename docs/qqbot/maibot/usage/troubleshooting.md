# 故障排查

按“平台连接、消息接收、模型请求、回复发送”的顺序检查，可以确定故障发生的位置。

## 查看日志

1. 打开左侧的 `日志`。
2. 回到 QQ，发送一句容易辨认的测试消息，例如“麦麦，今天过得怎么样”。
3. 查看这个时间附近的日志，先看是否收到了消息，再看是否出现错误。

| 日志中的情况 | 下一步 |
| --- | --- |
| 完全没有收到测试消息 | 检查 QQ 连接状态和适配器名单 |
| 收到消息后出现模型或鉴权错误 | 打开模型库测试对应模型，检查密钥和余额 |
| 已生成回复，发送时报错 | 检查机器人发言权限、连接情况；官方机器人同时查看平台返回的错误 |
| 提示端口被占用 | 检查是否已经启动了 MaiBot，关闭重复启动的那一份 |

需要分享日志求助时，复制问题发生前后的一小段，附上操作步骤和接入方式。将其中的 API Key、AppSecret 和登录密码隐藏。


## 检查消息链路

| 现象 | 检查项目 |
| --- | --- |
| 协议端没有收到 QQ 消息 | 查看 QQ 是否在线，机器人是否在这个群里 |
| 适配器没有显示连接成功 | 核对服务地址、端口和 WebSocket Token，确认协议端已启用正向 WebSocket |
| 已连接，但 MaiBot 没收到消息 | 查看当前账号的群聊 / 私聊名单是否包含测试群或用户 |
| 收到消息后出现模型错误 | 回到模型库测试模型，检查密钥、账号余额和模型分工 |
| 生成了回复，QQ 中却没显示 | 查看同一时间的发送错误，检查机器人是否被禁言及协议端是否在线 |

## WebUI 无法访问

1. 查看启动日志，确认 WebUI 已启动，并记录实际端口。
2. 本机部署时，使用 `http://127.0.0.1:<端口>`。
3. 服务器部署时，检查工作区 `host/config.toml` 中的监听地址，以及云平台安全组和系统防火墙。
4. NAT 服务器同时检查内外网端口映射。

完整设置见 [WebUI 访问与登录](/qqbot/maibot/config/webui)。

## QQ 官方机器人问题

| 现象 | 检查项目 |
| --- | --- |
| 鉴权失败或 401 | AppID 与 AppSecret 是否来自同一机器人，重置凭据后是否已重新保存 |
| 单聊正常，群聊无消息 | 平台群聊权限、机器人入群状态、群主设置的消息获取范围 |
| 已连接但未回复 | 当前账号的接收规则、模型测试结果、同一时刻的错误日志 |
| 重复回复 | 官方与 OneBot 是否同时收发，身份同步与关联账号是否按需要配置 |
| 绑定命令无权限 | 命令管理中授权的用户 ID 是否与消息发送者一致 |

配置说明见 [QQ 官方机器人](/qqbot/maibot/adapters/qq-official) 与 [QQ 身份绑定与同步](/qqbot/maibot/adapters/qq-identity)。
